# Security Policy

## Что делает приложение

Synapse запускает локальный HTTP/HTTPS-прокси на `127.0.0.1` и открывает сайты в браузере с отдельным профилем. Имена резолвятся через DoH-сервер, заданный пользователем; если DoH не настроен или не ответил, используется системный резолвер.

## Модель угроз

- Прокси работает без аутентификации, но слушает только loopback. Пока приложение запущено, любой локальный процесс может использовать его как HTTP-прокси. Не запускайте Synapse на общем компьютере с недоверенными пользователями.
- Прокси не расшифровывает TLS: соединения к сайтам идут как `CONNECT`-туннель, сертификаты проверяет браузер.
- DoH-сервер и bootstrap-IP задаёт пользователь. Недоверенный резолвер видит DNS-запросы и может вернуть произвольные публичные адреса. Подмена DNS не обходит проверку TLS-сертификата, но влияет на доступность и маршрут.
- Режим `direct` у сайта отключает DoH для его домена и поддоменов: запросы резолвит система.
- Smart DNS (например, сервисы, возвращающие адрес своего шлюза) пропускает трафик через сторонний узел. Такой провайдер видит метаданные: домены, время, объём, ваш IP. Содержимое TLS ему недоступно, если вы не установили его корневой сертификат.
- `profiles/` содержит cookies и сессии сайтов, `logs/` — журнал, `config.json` — настройки. Всё лежит рядом с exe. Защищайте папку и не публикуйте её.
- Сборки не подписаны. Сверяйте SHA-256 с указанным в релизе и скачивайте только из GitHub Releases проекта.

## Сообщения об уязвимостях

Не открывайте публичный issue для уязвимости. Используйте приватный отчёт GitHub Security Advisories в этом репозитории: Security → Report a vulnerability. Приложите версию, шаги воспроизведения и журнал без персональных данных.
